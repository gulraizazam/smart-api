1. Overview & Objectives
This is the complete, consolidated build specification for the Cash Flow & Expense Management module. It supersedes all previous documents.

1.1 Primary Objectives
Real-time cash position: Exact balance at every branch, head office, and bank at any moment. Priority #1.
Expense tracking: Every outgoing payment documented with source, beneficiary, receipts, vendor/staff linkage.
Vendor accountability: Ledgers for everyone the business pays — suppliers, landlords, lawyers, service providers.
Team accountability: Track cash advances and expense submissions per staff member.
Fraud prevention: Built-in controls against financial manipulation by any party.
Access control: Granular role-based permissions. Least privilege.
Audit safety: Immutable action log. No record ever truly deleted.

1.2 What This Module Does NOT Do
NOT a full accounting/ERP system.
NOT an invoicing system (patient invoices handled elsewhere).
NOT payroll (salaries recorded as expenses, not computed).

2. System Context & Assumptions
2.1 Existing CRM Data (Inflows)
Patient payments already tracked: cash at branch, card, bank transfers. Tagged with branch and method. Module reads from existing records — no changes needed.

2.2 Operational Reality
Cash stays at branches: Each branch collects and holds cash. Expenses typically paid from own cash.
Head office as cash hub: Receives surplus cash from branches. Makes expenses directly.
Cross-branch payments: Expense for Branch A can be paid from Branch B, HO, or bank. Track both source and beneficiary.
Centralized accounting: One accountant. Entry = approval. No workflow.
Single bank account: One account for the business.
Dynamic branches: Currently 12. System reads dynamically, never hardcodes.

3. Module Initialization (Go-Live)
One-time setup when module is first deployed. Admin only.

3.1 Go-Live Date
Admin sets go-live date in Settings (e.g., April 1, 2026).
All patient payment queries filter by: payment_date >= go_live_date.
Historical payments before this date NOT included — value captured in opening balances.
Go-live date frozen after first period lock.
⚠ SECURITY: Without this filter, cash flow includes years of historical payments without matching expenses. All numbers wrong.
ℹ IMPL: cashflow_settings: key='go_live_date'. Global helper/trait for consistent filtering.

4.5 Balance Calculation
Balance = Opening + Inflows – Outflows + Transfers In – Transfers Out
Inflows = patient payments to this pool
Outflows = expenses from this pool + advances from this pool
Transfers In = cash in from other pools + staff returns
Transfers Out = cash out to other pools
ℹ IMPL: cached_balance via Observer. Nightly reconciliation job. Dashboard reads cache; reports use true calc.

14. Period Locking
Monthly. Admin-only lock/unlock.
Locked = no adds/edits/voids for that month.
Sequential: can’t lock March before February.
Current month never lockable.
On lock: snapshots every pool balance for fast historical reports.
On unlock: mandatory reason in audit. Changes during unlocked window in digest.
After FIRST lock: all opening balances + go-live date frozen permanently.

17.3 Design Rules
Dynamic pools: Observer on Branch. Auto-create/deactivate.
Cached balances: On pools + vendors. Observer-updated. Nightly reconciliation.
Soft deletes: On all models.
DECIMAL(15,2): All money. Never FLOAT.
Void not delete: voided_at + reversal. Original preserved.
DB::transaction: All multi-record ops (upfront vendor, void+reversal, transfer).
Audit immutable: No delete/update on audit logs. Ever.

18. Business Rules & Validations
18.1 Expenses
Amount > 0. Date not future. Not in locked period. Pool must be active.
Only creator or admin edits, open period only.
Void: admin only, reason mandatory, reversal entry created.
Warn if pool goes negative.
Vendor selected → auto vendor payment. Staff selected → auto reduce advance.
Above threshold → requires verification. Backdated > 7 days → auto-flag.
No attachment + above threshold → auto-flag.

18.2 Transfers
From ≠ To. Amount > 0. Date not future/locked. Warn negative. Above threshold: attachment.

18.3 Vendors
Admin-only CRUD. Name unique (case-insensitive). No hard delete with transactions.
Warn overpayment. Upfront: DB::transaction. Dormant report at 90 days.

18.4 Staff
Active users only. Warn if existing balance > 0. Return cannot exceed balance.
Flag perfect-match advances. Aging alerts.

18.5 Pools
New branch → auto pool (0) → notify admin. Deactivated → soft-deactivate → notify if balance > 0.
Opening balance frozen after first lock.

18.6 Reconciliation
Sum(Pool Balances) = Patient Payments – Expenses + Opening Balances – Staff Advances
Nightly job writes snapshot. Dashboard shows green/red.
